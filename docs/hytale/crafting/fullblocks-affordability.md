# FullBlocks ResourceTypes & Affordability Checking

## Summary

FullBlocks groups (e.g., `FullBlocks_Hardwood`) are **BlockGroup** assets, NOT ResourceType assets. They define **visual variant groups** for the Builders Bench UI cycling feature. They are completely separate from the `ResourceTypeId`-based crafting input system. All variants in a FullBlocks group share the **same recipe input** (the raw material), and interchangeability between variants is provided **for free** by the BlockGroup cycling UI — not by crafting a new recipe.

## 2. Recipe IS NOT Inherited — Each Variant Has Its Own

From `Item.java` line 271:
```java
.<CraftingRecipe>append(  // ← .append(), NOT .appendInherited()
    new KeyedCodec<>("Recipe", CraftingRecipe.CODEC),
    (item, s) -> item.recipeToGenerate = s,
    item -> item.recipeToGenerate
)
```

**`Recipe` uses `.append()`** — it is NOT inherited from the parent item. Each item must define its own `Recipe` section in the JSON to have a generated recipe. This is in contrast to `ResourceTypes` which uses `.appendInherited()` (line 274) and IS inherited from parent.

Since `Wood_Hardwood_Decorative` has `Parent: "Wood_Hardwood_Planks"`:
- **Recipe**: NOT inherited → Decorative has its own explicit `Recipe` section
- **ResourceTypes**: Inherited → Decorative inherits `[Wood_Planks, Fuel, Charcoal, Wood_Hardwood]` from Planks

### Implication for Ornate

`Wood_Hardwood_Ornate` also has `Parent: "Wood_Hardwood_Planks"` (inferred from FullBlocks group membership and Set pattern). It must also have an explicit `Recipe` section. The recipe input is almost certainly `ResourceTypeId: "Wood_Hardwood_Trunk"` (same as all other members).

## 3. How CraftingManager.matches() Works

From `CraftingManager.java` line 571:

```java
public static boolean matches(@Nonnull MaterialQuantity craftingMaterial, @Nonnull ItemStack itemStack) {
    String itemId = craftingMaterial.getItemId();
    if (itemId != null) {
        return itemId.equals(itemStack.getItemId());   // Exact itemId match
    } else {
        String resourceTypeId = craftingMaterial.getResourceTypeId();
        if (resourceTypeId != null && itemStack.getItem().getResourceTypes() != null) {
            for (ItemResourceType itemResourceType : itemStack.getItem().getResourceTypes()) {
                if (resourceTypeId.equals(itemResourceType.id)) {
                    return true;  // Any matching ResourceType on the item
                }
            }
        }
        return false;
    }
}
```

**Match resolution order:**
1. If recipe input has `itemId` → exact item match
2. If recipe input has `resourceTypeId` → scan item's `ResourceTypes[]` array for matching `id`

### What matches `ResourceTypeId: "Wood_Hardwood_Trunk"`?

## 4. How the Vanilla Builders Bench Handles FullBlocks Interchangeability

The `StructuralCraftingWindow` provides TWO mechanisms:

### Mechanism 1: Crafting from Raw Material

Flow in `StructuralCraftingWindow.getMatchingRecipes()`:
1. Player places a trunk item (e.g., `Wood_Oak_Trunk`) in the input slot
2. Engine scans ALL bench recipes, checking `CraftingManager.matches(recipe.input[0], inputStack)`
3. All recipes whose single input is `ResourceTypeId: "Wood_Hardwood_Trunk"` match
4. Result: **Planks, Decorative, AND Ornate** all appear as output options
5. Player selects which variant to craft
6. 1 trunk → 1 variant (any of the three)

### Mechanism 2: BlockGroup Cycling (Free Variant Swap)

From `StructuralCraftingWindow.handleAction()` — `ChangeBlockAction`:

```java
case ChangeBlockAction changeBlockAction:
    if (((StructuralCraftingBench)this.bench).shouldAllowBlockGroupCycling()) {
        this.changeBlockType(ref, changeBlockAction.down, store);
    }
```

`changeBlockType()` at line 187:
1. Gets the `BlockGroup` for the current input item via `BlockGroup.findItemGroup(item)`
2. Finds the next/previous item in the group (wrapping around)
3. **Replaces the item in the input slot** — `replaceItemStackInSlot(0, item, new ItemStack(nextId, quantity))`
4. **No resources consumed** — it's a free visual swap

So if a player has `Wood_Hardwood_Planks` in the input slot and cycles:
- Planks → Decorative → Ornate → Planks → ...
- The item physically transforms in the input slot
- No crafting occurs, no trunk consumed

### When `AllowBlockGroupCycling` is Enabled

The bench configuration `StructuralCraftingBench.shouldAllowBlockGroupCycling()` must be `true`. The vanilla Builders Bench has this enabled (sent via `windowData.addProperty("allowBlockGroupCycling", true)`).

## 5. FullBlocks vs ResourceTypes — Two Different Systems

| Concept | FullBlocks (BlockGroup) | ResourceTypes |
|---------|------------------------|---------------|
| **Asset type** | `BlockGroup` (loaded from `Item/Groups/`) | Tag array on `Item` |
| **Purpose** | Visual variant cycling in bench UI | Recipe input matching & material categorization |
| **Example** | `FullBlocks_Hardwood`: `[Planks, Decorative, Ornate]` | `Wood_Hardwood_Trunk`: tag on trunk items |
| **Used by** | `StructuralCraftingWindow.changeBlockType()` | `CraftingManager.matches()`, `ItemContainer.removeMaterials()` |
| **Cost** | Free swap | Consumes input items |
| **Loaded as asset** | Yes — `AssetRegistry.getAssetStore(BlockGroup.class)` | No — inline array on Item, validated by `ResourceType.VALIDATOR_CACHE` |

### Are ResourceType assets loaded via AssetRegistry?

**No.** `ResourceType` in the decompiled source refers to the ECS `com.hypixel.hytale.component.ResourceType` (a component system concept), NOT crafting resource types. The `ItemResourceType` entries in item JSON (`ResourceTypes: [{Id: "Wood_Hardwood_Trunk"}]`) are just inline tagged values validated against a `ResourceType.VALIDATOR_CACHE` — they are NOT loaded as standalone assets with their own `AssetStore`.

BlockGroup, however, IS a full asset with its own `AssetStore<String, BlockGroup, DefaultAssetMap<String, BlockGroup>>`.

## 6. Affordability Checking for FullBlocks Recipes

### For your plugin's affordability check:

When checking if a player can afford a FullBlocks recipe:

1. **Get the recipe input**: Always `MaterialQuantity` with `resourceTypeId` (e.g., `"Wood_Hardwood_Trunk"`)
2. **Check inventory**: Use `ItemContainer.canRemoveMaterials()` or replicate its logic:
   - For each item in inventory, call `ItemContainer.getMatchingResourceType(item, resourceTypeId)`
   - If non-null, that item satisfies the requirement
   - Sum quantities considering `ItemResourceType.quantity` (usually 1)
3. **FullBlocks interchangeability is free**: If the player has any variant (Planks/Decorative/Ornate), they can cycle to any other variant for free — no affordability check needed for cycling.

### The engine's actual removal flow:

```
CraftingManager.removeInputFromInventory()
  → ItemContainer.removeMaterials(List<MaterialQuantity>)
    → InternalContainerUtilMaterial.internal_removeMaterials()
      → For each MaterialQuantity:
        - If has itemId → remove by exact item match
        - If has resourceTypeId → InternalContainerUtilResource.testRemoveResourceFromItems()
          → ResourceQuantity.getResourceType(slotItem)
            → ItemContainer.getMatchingResourceType(item, resourceId)
              → Scans item.getResourceTypes() for matching id
```

### Key insight for affordability:

**The same trunk item can satisfy the recipe for ANY of the three FullBlocks variants.** All three recipes require `Wood_Hardwood_Trunk`, and any item whose `ResourceTypes` includes `Wood_Hardwood_Trunk` (Oak Trunk, Ash Trunk, etc.) can be used. The total cost is always 1 trunk per block, regardless of which visual variant is chosen.

## 7. Gotchas

1. **Recipe is NOT inherited** — if you create a custom item with `Parent: "Wood_Hardwood_Planks"`, it will NOT get a recipe unless you add an explicit `Recipe` section.
2. **ResourceTypes ARE inherited** — a child item inherits the parent's ResourceTypes if not overridden.
3. **FullBlocks group membership does NOT affect crafting** — being in `FullBlocks_Hardwood` only enables BlockGroup cycling in the UI. It does not change recipe inputs, outputs, or matching.
4. **Planks cannot satisfy trunk recipes** — `Wood_Hardwood_Planks` has ResourceType `Wood_Hardwood` but NOT `Wood_Hardwood_Trunk`. These are different ResourceType IDs.
5. **BlockGroup cycling replaces the physical item** — it's not cosmetic. The item ID changes in the slot. If the player then breaks the block, they get the cycled variant.
